Results 与 Ablation：一个分数究竟证明了什么？

Architecture mechanism 解释模型怎样计算；experiment 则检验这套设计在特定 data、training、checkpoint selection 与 decoding pipeline 下产生了什么结果。Table 2 回答“完整系统是否有竞争力”，Table 3 尝试回答“哪些 design choices 与结果变化相关”，但二者都不是无条件的普遍因果证明。

前置：Lesson 0010 · 数学：exponential 与 logarithm · 主证据：Vaswani et al., §6、Tables 2–3

先把 reported score 放回 evaluation pipeline

Training setup
dataset、tokenization、model size、optimizer、schedule、regularization 与 training steps。
↓
Checkpoint selection
选择单个 checkpoint，或对多个 checkpoints 的 parameters 求平均。
↓
Decoding
beam search、beam size、length penalty 与 maximum output length。
↓
Metric
在指定 dataset split、tokenization 与 metric implementation 下计算 BLEU 或 perplexity。

因此“Transformer big 得到 \(28.4\) BLEU”不是 architecture 单独产生的数字，而是整个 evaluation pipeline 的 output。若 pipeline 中任一环节改变，score 也可能改变。

Reported BLEU 还包含哪些 decoding choices？

论文在 §6.1 同时给出：

  • Base models：平均最后 \(5\) 个 checkpoints；这些 checkpoints 每 \(10\) 分钟保存一次。
  • Big models：平均最后 \(20\) 个 checkpoints。
  • Beam search：beam size \(4\)。
  • Length penalty：\(\alpha=0.6\)。
  • Maximum output length：input length \(+50\)，允许提前终止。
  • Beam 与 length-penalty hyperparameters：在 development set 上实验后选择。

Checkpoint averaging 仍得到一个 model，但其 parameters 已不是某一个原始 checkpoint；beam search 与 length penalty 则改变如何从 next-token distributions 构造最终 sequence。因而 Table 2 比较的是 paper-defined systems，而不是只比较 forward equation。

Training Cost (FLOPs) 是 estimate，不是 energy measurement

论文用下式估计 training floating-point operations：

\[ C_{\mathrm{est}} =T_{\mathrm{train}} \times N_{\mathrm{GPU}} \times F_{\mathrm{sustained}}, \]

其中 \(T_{\mathrm{train}}\) 是 training wall-clock seconds，\(N_{\mathrm{GPU}}\) 是 GPU 数量，\(F_{\mathrm{sustained}}\) 是作者估计的单张 GPU sustained single-precision throughput，单位为 FLOPs/s。以 big model 的 P100 context 为例：

\[ \begin{aligned} C_{\mathrm{est}} &=(3.5\times24\times3600)\,\mathrm{s} \times8 \times9.5\times10^{12}\,\mathrm{FLOPs/s}\\ &\approx2.3\times10^{19}\,\mathrm{FLOPs}. \end{aligned} \]

这复算了 Table 2 对 Transformer big EN–DE 列出的数量级。它适合在论文采用的估计口径下比较 training arithmetic，但不等于 measured energy、cloud price、memory consumption、communication overhead 或现代 accelerator 上的 efficiency。

Table 3 的 development-set PPL 是 per-wordpiece perplexity。设有效 wordpiece positions 数为 \(N\)，其平均 negative log-likelihood 为：

\[ \overline{\mathcal{L}}_{\mathrm{NLL}} =-\frac{1}{N}\sum_{i=1}^{N}\log p(y_i\mid y_{<i},x), \qquad \operatorname{PPL} =\exp\!\left(\overline{\mathcal{L}}_{\mathrm{NLL}}\right). \]

因为 denominator 的 unit 是 wordpiece，不能把这些数值直接与 per-word perplexity 比较。这是 metric scope 的差异，不是简单的单位标签差异。

Table 3 应怎样读？

RowsObserved comparison可以说什么不能直接说什么
(A) heads在 paper-defined constant-compute design 下，\(1\) head 为 \(24.9\) BLEU；best setting 为 \(25.8\)；\(32\) heads 降至 \(25.4\)。在这些 tested settings 中，single head 比 best 低 \(0.9\) BLEU，heads 过多也下降。不能推出“head 越多越好”或存在跨模型通用的最佳 head count。
(B) key size把 \(d_k\) 从 base 的 \(64\) 降到 \(32\) 或 \(16\)，BLEU 分别为 \(25.4\)、\(25.1\)。在这些 variations 中，更小的 key dimension 与更差质量相关。作者关于 compatibility function 可能需要更复杂形式，是 hypothesis，不是 Table 3 直接证明。
(C) capacity较少 layers、较窄 \(d_{\mathrm{model}}\) 或较小 \(d_{\mathrm{ff}}\) 通常更差；tested larger settings 通常更好。在该 EN–DE dev setup 中，增加 tested capacity 改善结果。不能推出任意增大 depth/width 都持续改善；不同 subgroups 也不是一个统一的单变量实验。
(D) regularization\(P_{\mathrm{drop}}=0\) 为 \(24.6\) BLEU，base \(0.1\) 为 \(25.8\)；label smoothing variations 也改变 PPL/BLEU。Dropout 对该 setup 的 generalization 很重要。不能由一张表确定任意 dataset 的最佳 dropout 或 smoothing strength。
(E) positionLearned positional embeddings 为 \(25.7\)，sinusoidal base 为 \(25.8\)。两种方案在该 comparison 中近似。不能推出二者在 length extrapolation、其他 tasks 或更长 context 上等价。
Big row 不是单因素 ablation：它同时改变 \(d_{\mathrm{model}}\)、\(d_{\mathrm{ff}}\)、head count、dropout、training steps 与 parameter count。Big 的 \(26.4\) dev BLEU 证明完整 big configuration 在该 setup 下更好，不能把全部增益归因给其中一个 dimension。

Ablation 提供的是哪一级 evidence？

Observed result
指定 variation 在 newstest2013 dev 上得到某个 PPL / BLEU。
↓
Local comparison
在作者保持不变的其他配置下，variation 与 base 的结果不同。
↓
Mechanism interpretation
作者依据差异提出关于 compatibility、capacity 或 overfitting 的解释。
↓
General claim
若要推广到其他 architectures、datasets、scales 或 training regimes，需要额外实验。

Table 3 没有报告 repeated-run distribution、error bars 或 statistical test。因此 \(25.7\) 与 \(25.8\) 这样的微小差异足以支持“在该表中近似”，却不足以证明两个方法严格等价。Development-set results 还承担了 model choice / hyperparameter exploration 的角色，不能和 untouched test evidence 混为一谈。
