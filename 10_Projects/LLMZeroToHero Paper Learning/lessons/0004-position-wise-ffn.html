Lesson 0004 · 约 12 分钟

Position-wise Feed-Forward Network：取回信息之后，如何处理一个 token？

attention 解决“当前位置该从哪些 positions 取信息”。信息汇聚到 token state 后，Transformer 还需要一个不混合 token positions、但能做高容量非线性变换的模块：Position-wise Feed-Forward Network（FFN，逐位置前馈网络）。

前置：课程 0003 · 术语：Attention Glossary · 主证据：Vaswani et al. (2017), §§3.1, 3.3

先看一层 Transformer 缺少的能力

attention sub-layer（attention 子层）让 token \(i\) 用 \(Q/K/V\) 从其他 positions 汇聚 context。例如 cross-attention 将 source information 写回当前 Decoder state。但 attention 的主要职责是跨位置 routing / mixing（路由与混合）：决定从哪里读、按何种权重聚合。

汇聚后的 token state 还需要被解释、重组为对下一层有用的 features。原论文因此在每个 Encoder layer 与 Decoder layer 中都放入 FFN；它不再选择或读取其他 positions，而是对每一个已含上下文的 token vector应用同一个非线性函数。

attention
token \(i\) 从允许可见的 positions 汇聚 information，得到 contextual state \(z_i\)。
↓
position-wise FFN
只处理 \(z_i\) 自身，扩展、施加非线性、再投影回 model width。
↓
下一层
得到更新后的 token representation；下一层 attention 可再让 positions 交换信息。
一句话分工：attention 决定从哪里取；FFN 决定 token 在取回上下文后怎样变换。attention 本身也含 softmax 等非线性；这里的重点是 FFN 提供独立于位置混合的、逐 token 的非线性计算容量。

原论文中的 FFN 公式与形状

对任一 position 的输入 row vector x，原始 Transformer 使用两次 Linear（线性变换），中间使用 ReLU activation（激活函数）：

\[ \operatorname{FFN}(x)=\max(0,xW_1+b_1)W_2+b_2. \] \[ \begin{array}{c|c} x & [d_{\mathrm{model}}]\\ W_1,b_1 & [d_{\mathrm{model}},d_{\mathrm{ff}}],\ [d_{\mathrm{ff}}]\\ \text{hidden} & [d_{\mathrm{ff}}]\\ W_2,b_2 & [d_{\mathrm{ff}},d_{\mathrm{model}}],\ [d_{\mathrm{model}}]\\ \operatorname{FFN}(x) & [d_{\mathrm{model}}] \end{array} \]

若一层输入是 \(Z[n,d_{\mathrm{model}}]\)，则每一行独立计算：

\[ \operatorname{FFN}(Z)[i,:]=\operatorname{FFN}(Z[i,:]), \qquad \operatorname{FFN}(Z)\in\mathbb{R}^{n\times d_{\mathrm{model}}}. \]

因此，给定 \(Z\) 后，FFN 输出的第 \(i\) 行不直接读取 \(Z\) 的第 \(j\) 行。token-to-token communication 已发生在前面的 attention；FFN 对各行并行执行同一个函数。

为什么要先 expand，再缩回？

若两次 Linear 中间没有 activation，它们可以合并为一次 Linear，表达能力不会因“多一层”而本质增加。ReLU 使这段计算成为 non-linear（非线性）变换；中间的 \(d_{\mathrm{ff}}\) 维 hidden layer 则给它更多可学习的中间 features。

原论文的 base configuration 取 \(d_{\mathrm{model}}=512\)、\(d_{\mathrm{ff}}=2048\)。对一个 token，路径是：

\[ [512]\xrightarrow{\mathrm{Linear+ReLU}}[2048] \xrightarrow{\mathrm{Linear}}[512]. \]

输出回到 \(d_{\mathrm{model}}\)，使它能和 residual path 相加并作为下一层的统一接口。这里的 \(2048\) 个 hidden coordinates 是 learned capacity，不应解读为预先指定的 \(2048\) 个可解释语义槽位。

“position-wise”和“identically”各自约束什么？

论文用词它排除什么实际含义
position-wise
（逐位置）		FFN 内部的 token-to-token mixingposition \(i\) 只处理自己的 vector；它不会在 FFN 中直接访问 position \(j\)。
separately
（分别）		必须按 sequence length 串行处理所有 rows 可并行执行同一组 matrix multiplications。
identically
（相同地）		每个 position 一套独立参数同一 layer 的所有 positions 共享 \(W_1\)、\(b_1\)、\(W_2\)、\(b_2\)；不同 layers 使用不同参数。

原论文也指出，可将它视为两个 kernel size 为 1 的 convolutions：它描述的是“同一局部位置上的 channel transform”，并不表示在 sequence 维做了邻域卷积。

成本边界：不混合 positions，不代表成本可忽略

忽略 bias 时，单层 FFN 约有 \(2d_{\mathrm{model}}d_{\mathrm{ff}}\) 个权重，处理 \(n\) 个 tokens 的 dense compute 也与 \(2nd_{\mathrm{model}}d_{\mathrm{ff}}\) 成正比；它随 sequence length 线性增长，不会物化 \(n\times n\) attention score matrix。

在原论文的 \(512/2048\) 配置下，FFN 约有 \(2\times512\times2048\approx2.10\mathrm{M}\) 个权重；而一个 Multi-Head Attention block 的 \(Q/K/V/O\) 四个 \(d_{\mathrm{model}}\times d_{\mathrm{model}}\) projections 合计约 \(4\times512^2\approx1.05\mathrm{M}\) 个权重。FFN 不负责跨 token 通信，却承担了显著的参数与 compute。

边界：这只是原论文 dense FFN 的参数与主矩阵乘估算，不包含 activation、bias、LayerNorm、attention score、batch 或 kernel 实现细节。不能据此直接断言某个实际模型的 runtime bottleneck。
