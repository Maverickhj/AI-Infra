# 推理系统与训练对齐

## 推理系统的两阶段

- **Prefill**：并行处理 prompt，建立各层 KV cache。
- **Decode**：每步处理新 token，读取历史 KV，生成下一个 token 分布。

Continuous batching 会让请求动态加入、退出和重排；因此一个 batch index 不是稳定的请求身份。调试必须保留 request/session/rid 与 token range 的映射。

## 训练与推理为何会不同

| 边界 | 可能差异 |
| --- | --- |
| Processor | chat template、special tokens、媒体缩放/切块 |
| Position | RoPE scaling、M-RoPE、packed reset、cache offset |
| Mask | causal、padding、prefix、EOS/role/loss mask |
| 权重 | checkpoint 转换、shard/gather、量化、weight sync 时刻 |
| 算子 | fused/native、FlashAttention 后端、归约顺序 |
| Dtype | storage、autocast、accumulate、LM head、log-softmax |
| 调度 | 完整序列 forward 与 prefill/decode、chunked prefill |
| 输出 | raw logits、processed logits、sampler logits、selected-token log-prob |

## 对齐的对象层级

“输出一致”应拆成逐级契约：

1. request/sample 身份一致。
2. token IDs、媒体输入与 special-token 插入一致。
3. position IDs 和 attention mask 一致。
4. 权重版本、参数名映射和 shard 重建一致。
5. 选定模块输入一致。
6. 模块输出在允许误差内一致。
7. logits 处理与 log-prob 语义一致。

上游层级未证明时，直接比较末端 log-prob 通常无法定位原因。

## 权重同步的时间语义

在 RL 系统中至少可能存在 actor learner、rollout engine、reference model 多份权重。记录：

- 参数属于哪个角色和 global step。
- weight update 何时开始/完成。
- 请求是在同步前还是同步后进入 engine。
- cache 是否跨权重版本复用。
- checkpoint/export 转换是否包含全部层和特殊模块。

## Logits 与 Log-prob

不要把以下对象混称为“logits”：

- LM head matmul 的 raw logits。
- vocabulary-parallel gather 前后的 logits。
- temperature、penalty、mask 处理后的 logits。
- sampler 选择 token 时使用的 logits。
- 对选定 token 计算的 log-prob。

每一层都可能改变 dtype、shape 或数值语义。RL 中旧策略 log-prob、当前策略 log-prob 和 reference log-prob 还具有不同的训练角色。

## 可观测性最小字段

```text
request/session/sample id
role and global step
token ids hash + length
media hash + processor metadata
position ids hash
module path + layer + phase
global/local shape + dtype
TP/PP/CP/DP coordinates
weight version/checkpoint id
```
