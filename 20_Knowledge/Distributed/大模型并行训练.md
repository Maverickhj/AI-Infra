# 大模型并行训练

> [!warning]
> 并行维度的具体约束和通信实现随框架、模型与版本变化。本文给出分析坐标系，不替代目标仓库代码与配置验证。

## 总原则

并行策略回答三个问题：**切什么、谁持有、何时通信**。只背缩写无法判断显存、性能或正确性。

若多个并行维度彼此正交，典型 world size 关系为：

$$
W = D_{dp}D_{tp}D_{pp}D_{cp}D_{ep},
$$

但某些框架中 EP 与 DP/TP group 的组合并非简单乘法，必须以实际 process group 构造为准。

## 并行维度速查

| 维度 | 主要切分对象 | 典型通信 | 主要收益 | 典型代价 |
| --- | --- | --- | --- | --- |
| DP | batch / 样本 | gradient all-reduce 或 reduce-scatter | 扩吞吐 | 参数或 optimizer 状态复制/分片 |
| TP | hidden、head、vocab、矩阵维 | all-reduce、all-gather、reduce-scatter | 单层参数与计算分摊 | 高频层内通信 |
| PP | layer / stage | activation send/recv | 模型深度分摊 | bubble、stage 不均衡 |
| CP | sequence | all-gather、ring 或 all-to-all attention | 长序列激活分摊 | attention 通信与整除约束 |
| EP | experts | token all-to-all | MoE 参数/计算分摊 | 路由不均与 all-to-all |
| SP | sequence activation，常与 TP 绑定 | reduce-scatter/all-gather | 非 TP 区域激活分摊 | 实现依赖强 |

## Data Parallelism（DP）

每个 DP replica 处理不同数据。需继续区分：

- 参数是否复制。
- gradient 是否分片。
- optimizer state 是否分片。
- checkpoint 是全量、分片还是 distributed checkpoint。

“开启 distributed optimizer”不能自动推出所有模型状态按 DP 等比例缩小；要逐项看参数、master weights、moments、grad buffer 和通信 bucket 的所有权。

## Tensor Parallelism（TP）

TP 通常切线性层的输入或输出维，并在残差边界附近恢复完整语义。分析某层时记录：

- 参数分片轴。
- 输入是复制还是分片。
- 输出是复制还是分片。
- collective 在 forward 还是 backward。
- vocabulary/head padding 与 GQA KV 复制策略。

## Pipeline Parallelism（PP）

PP 按 layer 切 stage。显存与性能不仅由 stage 层数决定，还受 pipeline schedule、in-flight micro-batch 数、首尾 stage 的 embedding/LM head/vision encoder、重计算和虚拟 pipeline 影响。

Pipeline 报错必须先定位 stage/rank；下游 send/recv 或 collective 错误可能只是上游 rank 已经异常退出。

## Context Parallelism（CP）

CP 切序列轴，主要解决长序列 attention/activation 压力。必须核对：

- Q head 数、TP 与 CP 的整除关系。
- position IDs、causal mask 与 packed boundary 的局部构造。
- attention 使用 ring、all-gather、all-to-all 还是其他算法。
- 哪些子模块真正进入 CP，哪些会恢复完整序列。

顶层存在 `context_parallel_size` 或 `sequence_parallel` 配置，不等于视觉编码器、processor 或所有 attention 实现都实际采用相同切分。

## Expert Parallelism（EP）

EP 把 experts 分配到 rank，并把 token dispatch 到其目标 expert。性能取决于 token 分布，而非只有 FLOPs。需要观察每个 expert 的 token count、capacity/drop、all-to-all 大小、overlap 与 straggler。

## 选择并行策略的顺序

1. 写清模型结构、最大 token/media 规模和每步目标 batch。
2. 做参数、optimizer、gradient、activation、KV/cache、workspace 的粗预算。
3. 写出模型硬约束：head/expert/layer 的整除、vision 子模型限制、checkpoint 兼容。
4. 先选择满足容量的 TP/PP/CP/EP，再用 DP 扩吞吐。
5. 检查 stage 负载与通信拓扑。
6. 用小规模正确性实验和目标规模 profiler 验证。

## 常见误区

- 将 global world size 直接当成某个 parallel group size。
- 只看配置值，不看 enable condition 与 process group 实际构造。
- 认为 TP=1 时任何名为 sequence parallel 的配置都有效。
- 认为 CP 等比例缩小所有视觉与语言激活。
- 从参考配置复制 PP/CP/EP，而没有重新计算 world size、首尾 stage 和 checkpoint 布局。
